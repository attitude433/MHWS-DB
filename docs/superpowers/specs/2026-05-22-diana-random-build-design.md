# 다이애나 랜덤 빌드 (`.랜덤`) 설계

작성일: 2026-05-22
대상 기능: 랜덤 장비 추천 — 무기·방어구·호석·장식주 자동 조합

---

## 1. 목적

카톡방에서 `.랜덤` 한 번이면 시리즈/그룹 스킬 1개 발동이 보장된 풀세트 빌드(무기 + 방어구 5부위 + 호석 + 부위별 장식주 1개)를 즉시 받는다. 다이애나가 자연어로 "세팅 짜줘" 같은 요청을 받으면 같은 함수를 도구로 호출해 한 줄 코멘트와 함께 답한다.

성공 기준:
- 매 호출이 다양한 시리즈/조합을 뱉는다 (같은 빌드 반복 거의 없음)
- 시리즈 스킬 또는 그룹 스킬이 항상 정확히 1개 발동
- 와일즈 룰 위반 없음 (상위 방어구만, 최종 강화 무기/호석만, 슬롯 사이즈 매칭)

비목표 (YAGNI):
- 스킬 시너지 최적화 — 일부러 안 함, 무작위가 컨셉
- 사용자 입력 조건 (몬스터 / 무기 종류 지정) — 1차에선 X
- 풀세트 외 부분 빌드

## 2. 데이터 풀

| 구성 | 풀 크기 | 출처 |
|---|---|---|
| 최종 강화 무기 | 439개 | `data/equipment/weapons_all.json` — `crafting.branches == []` 인 leaf |
| R4↑ 5피스 시리즈 | 114개 | `data/equipment/armor.json` — `rarity >= 4` && `pieces.length == 5` |
| ↳ set_bonus 보유 | 62개 | 위 + `set_bonus != null` |
| ↳ group_bonus 보유 | 100개 | 위 + `group_bonus != null` |
| 최종 호석 | 64개 | `data/equipment/charms.json` — 각 `series_id` 의 `level` 최댓값 |
| 장식주 | (스킬 합집합) | `mapping/skill_to_equipment_1.json` — 각 스킬의 `accessories[]` |

장식주 풀은 모든 스킬의 `accessories` 를 평탄화해 `(name_kr, slot_level, allowed_on_kr, level)` 튜플 목록으로 만든다. 같은 `name_kr` 가 여러 스킬에 중복 등장하므로 (예: `파룡-KO주【3】` 는 파룡내성+KO 둘 다에 잡힘) 이름 기준 중복 제거 후 사용.

## 3. 알고리즘

### 3.1 발동 모드 선택

균등 확률로 1개 선택:

| mode | 발동 스킬 | 필요 부위 |
|---|---|---|
| `set_lv1` | set_bonus Lv1 | 같은 시리즈 2P + 자유 3P |
| `set_lv2` | set_bonus Lv2 | 같은 시리즈 4P + 자유 1P |
| `group` | group_bonus Lv1 | 같은 시리즈 3P + 자유 2P |

각 mode 의 후보 시리즈 풀:
- `set_lv1` / `set_lv2`: set_bonus 시리즈 62개
- `group`: group_bonus 시리즈 100개

### 3.2 방어구 픽

1. 모드에 맞는 후보 시리즈 풀에서 1개 시리즈 무작위 선택 (이를 "발동 시리즈"라 부름)
2. 발동 시리즈의 5피스 중 N개(N = 2/4/3)를 무작위로 골라 그 부위(head/chest/arms/waist/legs)를 채움
3. 남은 부위는 R4↑ 5피스 시리즈 풀 114개에서 부위별로 무작위 선택 (발동 시리즈와 우연히 겹치는 것도 허용 — 그 결과 모드보다 더 강한 발동이 일어나는 것도 OK. 예: `set_lv1` 모드에서 자유 부위가 발동 시리즈와 같아져 4P가 되면 Lv2 발동. 발동 자체는 항상 보장됨)

방어구 5피스 정렬 순서 (인게임 슬롯 순): `head` → `chest` → `arms` → `waist` → `legs`. 출력 시 부위 라벨은 표기하지 않고 이 순서로만 나열한다.

### 3.3 무기 픽

439개 leaf 중 무작위 1개.

### 3.4 호석 픽

64개 최종 호석 중 무작위 1개.

### 3.5 장식주 픽 (부위별 첫 번째 슬롯만)

각 장비의 `slots` 배열에서 **인덱스 0** 의 슬롯 사이즈만 참조한다.

- 무기: `slots[0]` 이 있으면 → 장식주 풀에서 `allowed_on_kr in ("무기", "양쪽")` && `slot_level <= slots[0]` 인 거 무작위 1개
- 방어구 각 부위: `slots[0]` 이 있으면 → `allowed_on_kr in ("방어구", "양쪽")` && `slot_level <= slots[0]` 인 거 무작위 1개
- 슬롯 자체가 없거나 첫 슬롯에 들어갈 후보 장식주가 없으면 그 라인의 장식주 표기 생략

## 4. 출력 형식

### 4.1 `.랜덤` / `.란듐` (명령어 직호출)

```
[랜덤 빌드]
무기: 라울 차지소드 (차지액스) — 공격주【3】
고어헬름β — 회피주【2】
흑식메일β — 회심주【3】
레우스암β — 도전주【3】
흑식코일β
흑식그리브β — 무기력주【2】
호석: 회피의 호석Ⅲ
발동: 흑식룡의 힘 Lv2
```

규칙:
- 무기 / 호석 / 발동 줄만 라벨 표기, 방어구 5부위는 라벨 없이 인게임 순(머리→동→권→요→각)으로 나열
- 슬롯 없는 부위는 ` — 장식주` 생략 (예: 위 4번째 줄)
- 발동 표시: `발동: {시리즈/그룹 스킬명} Lv{레벨}`
- 호석 표기는 이름만 (스킬은 이름에 함축, 옵션 A 컴팩트 유지)

### 4.2 다이애나 자연어 호출

도구 `get_random_build` 가 위 텍스트를 반환하고, Sonnet 이 다이애나 톤 한 줄 코멘트를 앞에 자연스럽게 붙임. 예:

```
오늘은 이걸로 한 번 나가봐요!

[랜덤 빌드]
...
```

코멘트는 Sonnet 이 매번 다르게 생성 — 풀 텍스트 별도 관리 안 함.

## 5. 호출 형태

- `.랜덤` — 정식 명령어
- `.란듐` — 숨김 alias (실행 O, `.명령어` 안내문에선 미노출)
- 다이애나 자연어 트리거 — "세팅 짜줘", "랜덤 빌드", "장비 추천 아무거나" 등 → `get_random_build` 도구 호출

## 6. 구현 위치

- `commands/random_build.py` (신규)
  - `generate_random_build() -> dict` — 위 알고리즘 실행, 빌드 dict 반환
  - `format_build(build: dict) -> str` — 4.1 텍스트 포맷팅
  - `random_build_text() -> str` — 위 둘을 조합한 진입점
- `commands/chat.py`
  - `TOOLS` 에 `get_random_build` 추가
  - `_exec_tool` 분기에 호출 추가 (인자 없음)
- `main.py`
  - `.랜덤` / `.란듐` 라우팅 추가 → `random_build_text()` 호출
- `.명령어` 안내문
  - `.랜덤` 한 줄 추가, `.란듐` 미노출

## 7. 엣지케이스

- **무기 슬롯 없음**: 무기 줄에 장식주 표기 생략
- **첫 번째 슬롯에 들어갈 장식주가 없음**: 해당 부위 장식주 라인 생략 (size 1 슬롯인데 장식주 풀에 size 1 가 없는 경우)
- **발동 시리즈 부위 수가 모자람**: 풀을 5피스 완비 시리즈로만 제한했으므로 발생 없음
- **호석/무기 데이터 비어 있음**: 빈 풀 검사 후 명확한 에러 메시지 — 데이터 무결성 문제이므로 fail loud
- **장식주 데이터 누락 (특정 스킬 entry 없음)**: 풀에서 자연 누락, 빌드 자체엔 영향 없음

## 8. 테스트 시나리오

- T1: 1000회 반복 호출 → 모든 빌드가 발동 스킬 1개 정확히 가짐
- T2: 1000회 중 mode 별 분포가 균등 (~333회씩, ±10%)
- T3: 1000회 중 동일 빌드 반복 < 1% (다양성 보장)
- T4: 슬롯 사이즈 룰 위반 0건 (장식주 size ≤ 슬롯 size)
- T5: 무기/방어구 장식주 풀 위반 0건 (allowed_on 룰)
- T6: 출력 텍스트가 빈 줄/오타 없음
