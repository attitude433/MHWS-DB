## 1. 목적

카톡방에서 매일 출석으로 제니를 쌓고 룰렛으로 불리거나 잃는 도박 시스템. 제니는 영구 누적되며 룰렛 "초기화" 당첨 시만 0으로 리셋. 랭킹으로 경쟁.

성공 기준:
- 출석 1일 1회 보상, 룰렛 1일 3회 베팅 제한 정확 동작
- 룰렛 확률표 10단계 균등 적용 (난수 분포 검증 가능)
- 잔고 일관성 — 베팅 금액만 영향, 잔고 음수 불가
- DB 영구 누적, 봇 재시작 후에도 보존
- 잭팟·초기화 시 방 공지 자동 발송

비목표 (YAGNI):
- 상품 보상 / 외부 환금
- 월별 초기화·시즌
- 친구 선물·이체
- 룰렛 외 미니게임

## 2. 명령어 명세

| 명령어 | 동작 | 안내 멘트 |
|---|---|---|
| `.출석` / `.출석체크` | 하루 1회 10~30 제니 (균등) 지급 | `출석 완료! +20제니 (현재: 150제니)` |
| `.출석` 중복 | 안내만 | `이미 오늘 출석했어요 (현재: 150제니)` |
| `.룰렛` | 사용법 안내 | `.룰렛 [금액] 또는 .룰렛 올 (오늘 3회 남음, 보유: 150제니)` |
| `.룰렛 [N]` | N 제니 베팅 (1≤N≤보유), 1일 3회 제한 | 결과 텍스트 (아래 §4 참고) |
| `.룰렛 올` | 보유 제니 전액 베팅 | 결과 텍스트 |
| `.룰렛 [N]` 잔고 부족 | 안내만 | `제니가 부족해요` |
| `.룰렛 올` 잔고 0 | 안내만 | `제니가 없어요` |
| `.룰렛` 횟수 소진 | 안내만 | `오늘 룰렛 횟수를 다 사용했어요` |
| `.룰렛 [N]` 음수/0 | 안내만 | `1 이상의 숫자를 입력해주세요` |
| `.룰렛 [잘못된 표기]` | 안내만 | `.룰렛 [금액] 또는 .룰렛 올 형식으로 입력해주세요` |
| `.제니` | 자기 잔고 조회 | `[닉네임] 현재 제니: 150` |
| `.제니순위` | 상위 10 + 보유자 전원 | (아래 §5 참고) |
| `.제니그래프` | 본인 일자별 잔고 라인 차트 (matplotlib + reply_media) | 숨은 명령어, HELP_TEXT 미노출 |

베팅 금액은 **순수 정수만**. `100제니`, `100z`, `반`, `만` 같은 표기 거부.

## 3. 룰렛 확률표 & 수익률 계산

| 결과 | 확률 | 수익률 (베팅 N 기준) |
|---|---|---|
| 초기화 | 0.1% | 잔고 전체 0 |
| -70% | 5.7% | N × 0.3 환급 |
| -50% | 17.2% | N × 0.5 환급 |
| -20% | 27.0% | N × 0.8 환급 |
| 0% | 10.0% | N 환급 (본전) |
| +20% | 16.7% | N × 1.2 환급 |
| +50% | 12.0% | N × 1.5 환급 |
| +70% | 8.0% | N × 1.7 환급 |
| +100% | 3.2% | N × 2 환급 |
| +1000% | 0.1% | N × 11 환급 (잭팟) |

확률 합 = 100.0%

**계산 모델:**
- 베팅 전 잔고: `B`
- 베팅 금액: `N`
- 결과 수익률: `r`
- 베팅 후 잔고 = `B - N + N × (1 + r)` = `B + N × r` (초기화 제외)
- 초기화 케이스: 잔고 = 0 (베팅 금액 차감과 무관, 전체 리셋)

**예시:**
- 잔고 100, 베팅 30, -20% → `100 - 30 + 24 = 94`
- 잔고 100, 베팅 30, +1000% → `100 - 30 + 330 = 400`
- 잔고 100, 베팅 30, 초기화 → 0

## 4. 룰렛 응답 형식

### 일반 결과 (이익/손실/본전)
```
🎰 룰렛 결과: -20%
30 → 24제니 (-6제니)
현재 제니: 94제니 (오늘 2회 남음)
```

### 잭팟 (+1000%)
방에 두 줄 발송:
```
🎰 룰렛 결과: +1000%
30 → 330제니 (+300제니)
현재 제니: 400제니 (오늘 2회 남음)
```
이어서 방 공지:
```
🎰 [닉네임]님이 잭팟을 터뜨렸습니다!! 제니가 폭발했어요! 💥
```

### 초기화 (0.1%)
```
💸 룰렛 결과: 초기화
30 → 0제니 (잔고 전부 소멸)
현재 제니: 0제니 (오늘 2회 남음)
```
이어서 방 공지:
```
💸 [닉네임]님의 제니가 전부 사라졌습니다... 아이루도 울고 있어요
```

방 공지는 룰렛 발생한 그 방으로만 발송 (운영방 별도 알림 없음).

## 5. `.제니순위` 출력 형식

```
[제니 랭킹]
🥇 1. 닉네임A — 4,633제니
🥈 2. 닉네임B — 3,820제니
🥉 3. 닉네임C — 2,140제니
4. 닉네임D — 1,580제니
...
10. 닉네임J — 320제니
---
[보유자 전체]
11. 닉네임K — 280제니
12. 닉네임L — 150제니
...
```

- 상위 10명: 메달 이모지 + 등수 + 닉네임 + 제니
- 보유자 전체: 상위 10 아래 1줄 1명
- **제니 0인 사람 제외**
- **동점 동순위** (예: 두 명 다 500 → 둘 다 "3." / 다음은 "5.")
- 카톡 메시지 1회 발송. 길이 제한 부딪치면 별도 처리는 1차 안 함 (현재 멤버 규모로 충분)

## 6. `.제니그래프`

- 본인 일자별 잔고 라인 차트
- 데이터: `zenny_history` 테이블에서 user_id 본인 row 전부
- 라이브러리: matplotlib (requirements.txt 추가)
- 출력: PNG 파일 임시 저장 → `ctx.reply_media([path])`
- x축: 날짜 (YYYY-MM-DD), y축: 제니
- 최근 60일만 표시 (이전 분량 누적되면 가독성↓)
- 데이터 0건이면 "그래프 그릴 기록이 없어요"
- HELP_TEXT 미노출 (숨은 명령어)

## 7. DB 설계

### 기존 테이블 확장 — `members`

```sql
ALTER TABLE members ADD COLUMN zenny INTEGER DEFAULT 0;
ALTER TABLE members ADD COLUMN last_attend TEXT;       -- 'YYYY-MM-DD' (KST)
ALTER TABLE members ADD COLUMN roulette_count INTEGER DEFAULT 0;
ALTER TABLE members ADD COLUMN last_roulette TEXT;     -- 'YYYY-MM-DD' (KST)
```

마이그레이션: 봇 시작 시 `PRAGMA table_info(members)` 로 컬럼 존재 검사 → 없으면 ALTER. 이미 있으면 skip. 멱등.

### 신규 테이블 — `zenny_history`

```sql
CREATE TABLE IF NOT EXISTS zenny_history (
    user_id TEXT NOT NULL,
    date    TEXT NOT NULL,    -- 'YYYY-MM-DD' (KST)
    zenny   INTEGER NOT NULL,
    PRIMARY KEY (user_id, date)
);
```

- 매 출석/룰렛 이후 해당 날짜 잔고 **upsert** (`INSERT OR REPLACE`)
- 같은 날 여러 번 동작 시 마지막 잔고만 보존

## 8. 타임존 / 자정 리셋

- 모든 날짜 계산 **KST (Asia/Seoul, UTC+9)**
- 자정 00:00 (KST) 기준으로 출석/룰렛 카운트 리셋
- 실제 작동: 호출 시점에 `today_kst()` 가져와서 DB 의 `last_attend`/`last_roulette` 와 비교. 다르면 카운트 0 으로 리셋 후 진행
- 별도 cron 작업 없음

## 10. 엣지케이스

- **출석 중복 시도**: 안내 멘트만, 보유 제니 그대로
- **룰렛 횟수 소진 시 `.룰렛`**: "오늘 룰렛 횟수를 다 사용했어요"
- **잔고 부족 베팅**: "제니가 부족해요"
- **잔고 0 + `.룰렛 올`**: "제니가 없어요"
- **음수/0 베팅**: "1 이상의 숫자를 입력해주세요"
- **잘못된 표기 (`.룰렛 만`, `.룰렛 100제니`)**: 사용법 안내
- **DB 마이그레이션 실패**: 봇 시작 시 즉시 fail loud
- **`.제니순위` 보유자 0명**: "아직 제니 보유자가 없어요"
- **`.제니그래프` 매년 도전 다 누적 (수년)**: 최근 60일 슬라이딩 윈도우
- **자정 직전 룰렛 → 자정 후 출석**: 출석 카운트는 정상 리셋, 룰렛 카운트도 리셋

## 11. 검증

`scripts/test_zenny_simulation.py`:

- 100명 가상 멤버 60일 시뮬
  - 매일 출석 (10~30 균등)

- 확률 분포 — 1만회 결과 분포가 확률표와 ±2% 이내
